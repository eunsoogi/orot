# Bottom-edge layout ownership

The app keeps scroll surfaces edge-to-edge. Safe-area protection belongs to final content and controls, not a permanent empty strip clipping the whole page.

## Shared contract

`NavigationViewport` extends every routed surface to its measured visible bottom, regardless of whether the route scene or its child owns scrolling. Top and lateral system/rail regions remain reserved. `useNavigationContentInset` supplies the larger of actual bottom-action overlap and the visible system bottom edge, plus the caller's reading/control gap. This protects both scrolling end items and the fixed conversation composer. A keyboard-contracted viewport removes the old home-area reservation. The navigation overlay position is unchanged.

`SafeAreaLayout` provides the separate standalone/modal contract. Its scrolling mode draws through the bottom edge and adds system clearance at the end, retaining the screen's original content gap. Native keyboard adjustment owns keyboard occlusion; system end clearance remains conservative for floating, hardware, and zero-height keyboard cases. Keyboard visibility alone never removes home-indicator protection. Fixed-control mode retains safe bounds because those controls cannot scroll out from underneath the home indicator. It is not a substitute for a scrolling page wrapper.

## Evidence and limits

Earlier calendar probes omitted the enclosing shell. They could verify colors/text but not the persistent clipping boundary. The first common implementation additionally keyed edge behavior to scene-owned scrolling, missing child-owned scrollers. Regression tests now exercise both ownership modes, side/bottom navigation, resize/keyboard transitions, and preserve edited state.

Component geometry tests are synthetic. Native observation must identify the source/bundle revision and runtime; it does not prove all Duo window configurations or real keyboard interactions. No private data or screenshots belong in this document.
