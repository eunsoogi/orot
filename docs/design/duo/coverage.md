On 2026-10-26, all 44 registered PNGs were visually reviewed in labeled contact sheets. The local `screens-v5` files and `github-assets` copies have matching SHA-256 digests for every reference. The review covers visible content and layout relationships; it is not a pixel comparison with the running app. The assets are expanded light-appearance mockups. They do not show dark appearance, larger text, keyboard-open forms, narrow Split View, or live loading and interaction behavior.

The follow-up on the same date rechecked the exact 44-image sets and SHA-256 digests against the immutable [registered asset commit](https://github.com/eunsoogi/orot/tree/435de568d8efb343ce0b90a6031977b433dc9d89). All local gallery and publication copies match that baseline, so the complete visual review is retained rather than claimed as a new review. Source changes still require the mapping updates below.

- P16 is titled as manual appointment entry, but its image shows the appointment list and add action, like P13. In the current app, `medical-manual` renders `AppointmentsScreen`, which owns the list and local create/edit form. The image is not evidence of a separate `ManualAppointmentScreen` presentation.
- P30 shows the routed evidence detail with a Back control and source metadata. Keep it separate from the conditional `SourceEvidenceSheet` used by the standalone visit-question view; the screenshot does not establish that the sheet has a separate Duo presentation.
- P42 shows an external-literature error presentation. P42-empty and P42-loading show local states of that same literature screen. They are examples, not a universal shared state renderer.
- P33–P41 were generated as proposed-feature references. P33/P34 map to the integrated symptom journal. P35–P41 now identify the current production owner relevant to each reference below; P38's source view shows saved extracted text and locators, not the original file. These mappings do not establish that a mockup is implemented or that its Duo layout was exercised.

The right navigation lane is visually reserved for controls in the expanded references. Static images cannot establish the native Liquid Glass material, the animated continuous selection indicator, accessibility behavior, or state retention after resizing. Those remain implementation and runtime checks.

Status meanings:

- **Connected**: an app caller and renderer were identified. This proves source reachability, not successful runtime execution.
- **Local state**: a form, selection, or panel inside a connected route; no additional route should be invented to match an image.
- **Planned connection**: the parent orchestration task records an intended entry path, but its production caller is not implemented. Keep current source reachability separate from the plan.
- **Represented or excluded wrapper**: existing content is represented on another surface or an unused wrapper is excluded from separate Orot App coverage. This does not remove code or establish behavior for external consumers.
- **Pending integration**: a proposed feature has no renderer in the inspected app tree. Its feature owner must supply the integrated route and states before adaptation.
