# 일일 보고서 해석 경계

2026-11-15 공개 원문을 확인했다. 사용자 기록이나 화면은 이 문서와 테스트에 포함하지 않는다.

## 현재 지원하는 해석

`dailyReportGuidance`는 모델이 작성한 진단 대신, 검증된 원본 기록에 연결된 제한적 교육 안내를 생성한다. 혈압은 mmHg의 개별 측정을 사용하며 커프 측정의 수 초 구간도 포함한다. 다른 기기/시각의 수축기·이완기 값을 한 쌍으로 만들지 않는다. 수치가 정상 범위처럼 보여도 전체 건강이 정상이라고 판정하지 않는다. 연령, 임신, 개인 목표, 측정 장소는 확인되지 않았으므로 성인 참고 기준의 적용 한계를 명시한다.

- [질병관리청 고혈압 안내](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=6765): 진료실 기준과 가정혈압 기준은 다르다. 가정혈압 135/85 기준은 반복 측정 평가의 참고 기준이며 단일값 진단에 사용하지 않는다. 염분 감소, 금연·절주 등의 생활 안내와 임의 약물 변경 금지를 포함한다. [가정혈압 기준 원문](https://health.kdca.go.kr/healthinfo/biz/health/ntcnInfo/healthSourc/thtimtCntnts/thtimtCntntsView.do?thtimt_cntnts_sn=28)을 함께 확인한다. 세부 개인 치료 목표를 구현하지 않았다.
- [AHA 가정혈압 안내](https://www.heart.org/en/health-topics/high-blood-pressure/understanding-blood-pressure-readings/monitoring-your-blood-pressure-at-home): 단일 높은 값은 재측정한다. 매우 높은 값과 흉통·숨참·신경학적 증상은 즉시 응급 연락 대상이며 증상 동반 시 재측정을 기다리도록 하지 않는다. AHA 원문은 180/120 초과라고 표기한다. 국내 안내의 180/120 이상 경계에 맞춰 경계값도 보수적 확인 대상으로 삼으며 이를 AHA의 정확한 경계라고 표현하지 않는다. 기록이 과거일 수 있으므로 현재 응급상태로 단정하지 않는다. 원본 값이 충돌해도 심한 값은 확인 안내에서 숨기지 않는다.
- [WHO 신체활동](https://www.who.int/news-room/fact-sheets/detail/physical-activity): 활동은 개인 능력과 상태에 맞춰 안내한다. 일부 걸음/운동 샘플로 하루 총량이나 운동 부족을 단정하지 않는다.
- [Apple HealthKit 권한](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data): 앱은 읽기 권한 거부를 알 수 없고 접근 가능한 기간도 제한될 수 있다. 운동 기록 부재는 실제 운동을 안 했다는 증거가 아니다.

## 보존과 한계

기존 저장 보고서는 생성 당시 원문을 보존한다. 원시 기록 목록은 기본 접힘으로 두되 사용자가 펼치고 출처로 이동할 수 있다. 새 보고서의 표시용 수치/항목/시각만 지역화하며 모델에 전달하는 원본 값은 변경하지 않는다.

이번 단계는 혈압과 활동 안내, 기존 패턴 요약 및 표시 개선이다. 전체 건강의 임상적 진단, 모든 측정 항목의 정상/이상 판단, 과거 기준과 생활 맥락을 종합하는 모델 품질은 입증하지 않았다. 이 한계를 이유로 데이터 없는 항목을 정상 또는 운동 부족으로 채우지 않는다. 원본 저장·동의·긴급 안전 경계는 유지한다. 합성 테스트만 사용하며 실제 모델·실기기 검증을 주장하지 않는다.

## 개인 맥락 확인 질문

후속 보고서는 당일 snapshot에 있는 지속 중 증상, 혈압, 걸음/운동 기록에 맞춰 현재 증상과 측정 조건, 의료진이 정한 목표, 실제 활동과 운동 제한을 묻는다. 해소된 증상을 현재 증상으로 바꾸지 않으며, 운동 기록 부재를 운동하지 않았다는 답으로 채우지 않는다. 매우 높은 혈압 기록이 있으면 응급 안내가 대화 답변을 기다리는 절차로 보이지 않도록 추가 질문을 생략한다. 질문 자체는 새 외부 요청을 만들거나 건강정보를 새로 읽지 않는다.

이는 개인 맥락 수집을 위한 단계이며 답변을 이미 수집했다거나 개인별 종합 진단을 완료했다는 뜻이 아니다. 기존 보고서 재사용 시 과거 질문과 내용은 그대로 유지한다. 답변을 반영한 후속 수정은 기존 출처·동의·저장 경계로 처리해야 하며, 평소 기준이나 임상 목표를 임의 추정하지 않는다.

## 데이터 우선 보고서로 정정

사용자 정정에 따라 새 보고서는 자동 확인 질문을 만들지 않는다. 기존 저장 보고서는 수정하지 않으며, 이미 접근 가능한 원본을 먼저 종합한다. 복약은 명시적인 복용·누락·건너뜀·불명 상태를 구별하고, 당일 증상 및 저장된 진료 일정과 함께 실천 안내로 연결한다. 일정은 실제 참석이나 처방 변경의 증거가 아니다. 아직 시작하지 않은 당일 일정도 생성 시각 전에 저장된 **계획**으로만 포함하며, 미래 건강 측정은 계속 제외한다. 일정의 수정·삭제는 저장 검증과 기존 출처 추적에 반영한다.

전체 EventKit 일정은 아직 이 경로의 원본이 아니며 앱에 확정해 저장한 진료 일정만 포함한다. 개인정보나 캘린더 원본 제목을 새로운 외부 요청으로 전달하지 않는다. 모델에는 기존 동의한 사실 선택 요청만 유지한다. 복약 약명·개인 처방 목표·장기간 기준에 근거한 종합 임상 해석은 아직 완성되지 않았다. 이 부족한 범위를 질문으로 대신하거나 실제 진단을 완료했다고 주장하지 않는다.

[NHS Specialist Pharmacy Service 복용 누락 안내](https://sps.nhs.uk/articles/advising-on-missed-or-delayed-doses-of-medicines/)를 2026-11-15 확인했다. 약마다 조치가 다르므로 특정 복용 시각/용량을 임의 추천하지 않고 처방 지침·약사·의료진 확인을 안내한다. 누락과 증상의 인과관계나 약효를 단정하지 않는다.

## 연결된 약 정보

당일 복약 기록이 명시적으로 참조하는 약 등록/처방 원본만 같은 트랜잭션에서 읽는다. 지정된 source 범위를 넘지 않으며 생성 시각 이후, 삭제, stale, 크기 제한으로 제외된 정보는 약명 미확인으로 남긴다. 과거 약 정보의 시각은 오늘로 바꾸지 않고 `supportingRecordFor`로 당일 복약 기록과 구별한다. 연결된 원본은 동의할 정확한 요청·revision·출처 참조·삭제 검증에 포함한다. 이름이 확인된 복약 상태와 실천 안내를 함께 표시하지만, 등록·처방이 실제 복용이나 현재 사용을 증명하지는 않는다.

## 시스템 캘린더 계획의 별도 출처 경계

보고서 날짜의 반열린 구간으로 읽기 가능한 시스템 캘린더 전체를 조회한다. 보고서 생성은 권한 요청·일정 가져오기·원본 변경을 하지 않는다. 명시적인 로컬 sourceIds 범위가 있으면 캘린더를 덧붙이지 않는다. 읽기 실패·권한 부족은 범위 한계이며 일정이 없다는 근거가 아니다.

제목에서 명시적인 진료·건강 또는 운동 계획만 로컬에서 보수적으로 분류한다. 취소 일정은 계획에서 제외하며 미확정·상태 미상은 확정 참석으로 바꾸지 않는다. 모델에는 계획 종류·건수와 불확실성만 전달하고 원제목·캘린더 ID·위치·참석자는 보내거나 보고서에 저장하지 않는다. 실제 운동·진료 수행, 복용, 진단은 일정에서 추론하지 않는다. 원격 요청은 calendar_plans를 포함한 정확한 payload 동의를 새로 확인한다.

system_calendar 출처는 로컬 임상기록 lineage로 위장하지 않는다. 별도 날짜 범위와 revision binding을 context에 저장하고, 동의 이후 provider 실행 전·저장·재열기·파생 artifact 사용 시 native 조회로 검증한다. 저장 보고서의 원본 변화·권한철회·확인 불가가 관측되면 해당 보고서를 stale 처리하여 과거 내용을 다시 정상 결과로 노출하지 않는다. 캘린더 기반 인용은 이 검증을 받는 생성 보고서의 계획 요약으로 표시하며 독립적인 임상 원문으로 표시하지 않는다. EventKit과 SQLite의 원자적 트랜잭션을 보장하지는 않으며 저장 직후에도 살아 있는 snapshot의 변경 여부를 확인한다.

이는 당일 계획 맥락의 안전한 통합이지 장기 개인 기준선·약효·상호작용 또는 종합 건강 진단의 완성이 아니다. 합성 provider는 사실 선택·동의·출처 경계만 검증하며 실제 모델의 개인별 해석 품질을 입증하지 않는다.

## 개인별 최근 관측 맥락

최근 28개 현지 날짜의 호환 가능한 점 측정(안정시 심박수·체중·혈압)을 오늘과 함께 살핀다. 동일 지표·단위·출처만 묶고 출처 식별자가 없는 외부 측정, 서로 충돌하는 같은 시각의 측정, 걸음·수면 같은 누적량은 비교에서 제외한다. 관측된 날짜마다 중앙값을 구한 다음 그 일별 값의 중앙값을 오늘의 중앙값과 비교한다. 최소 3개 관측일은 화면에 비교를 표시하기 위한 기준일 뿐 임상적 표본 충분성이나 정상 범위를 뜻하지 않는다. 28일 전체가 측정되었다고 가정하지 않으며 개인 과거값도 고혈압 등 주의 수치 안내를 무효화하지 않는다.

과거 자료는 `personal_baseline` 역할과 실제 발생·수집 시각을 보존하고 당일 관측 및 개수와 분리한다. 동일 SQLite 스냅샷·출처 범위·수집 마감·용량 제한과 기존 변경/삭제 추적을 적용하며 외부 모델에는 기존 정확한 입력 동의를 받은 비교 문장만 포함한다. 최대 100개 과거 후보와 남은 입력 용량 안의 관측값만 사용하며 제한에 걸린 범위는 부분 조회로 표시한다. 운동/복약의 장기 추세와 의학적 종합 진단은 이 서술 비교만으로 완료되지 않는다.
