# 일일 보고서용 시스템 캘린더 스냅샷

`listEventsInRange(fromInclusive, toExclusive)`는 기존 EventKit 읽기 권한이 있을 때 모든 읽을 수 있는 캘린더를 조회한다. 앱에 가져온 진료 일정만으로 제한하지 않는다. 시간 범위는 시작 포함·끝 제외이며, 겹치는 일정과 범위 안의 길이 0 일정도 포함한다. 호출자가 보고서 목적의 범위를 정하되 한 번에 32일을 넘을 수 없다. 캘린더 접근 권한 요청, 일정 가져오기·수정·삭제는 수행하지 않는다.

`readCalendarRangeSnapshot`은 전체 결과와 조회 범위를 검증하고 변경 알림을 구독한다. 권한 부족, 일부 직렬화 누락, 범위 불일치, 모호한 반복 일정은 빈 결과가 아니라 오류다. 재검증은 전체 범위를 다시 조회하여 추가·수정·삭제와 권한 변경을 확인한다. 사용을 마치면 `dispose()`로 구독과 보관 배열을 해제한다. 시간대·종일·반복 일정 정보는 원본 의미를 유지한다. 범위 조회 전용 `calendarStatus`는 취소·잠정·확정·미지정 계획을 구별하며, 상태 변경도 재검증에서 무효화한다. 확정 일정도 실제 참석 증거는 아니다.

제목과 식별자는 로컬 선별·재검증을 위한 자료다. 메모·위치·참석자 정보는 반환하지 않는다. 이 API 자체는 외부 제공자 전송 동의를 부여하지 않으며, 일정이 존재한다고 참석·운동·복약 완료로 해석하지 않는다. 보고서 연결부는 관련 일정만 최소화하여 기존 정확한 전송 내용 동의와 삭제·변경 방어를 적용해야 한다.

현재 이 변경은 읽기 포트와 로컬 스냅샷 기반이다. 보고서 생성 경로 연결과 제출 직전 재검증은 별도 통합이 필요하며, 이 기반만으로 보고서 기능이 완료된 것은 아니다. 합성 자료로 권한·범위·변경·삭제·중복 반복·수명 종료를 검사한다. 실제 사용자 캘린더나 건강 자료는 검증에 사용하지 않는다.
