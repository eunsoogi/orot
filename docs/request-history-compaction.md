# 대화 요청의 과거 질문 중복 제거

일반 대화의 요청 투영은 `previousConversation`의 사용자 질문 원문을
유지하고, `priorDialogue`의 질문이 그 원문과 정확히 같을 때만
`questionFromPreviousConversation`에 0부터 시작하는 배열 인덱스를 넣는다.
참조는 질문 문자열만 공유하며 두 목록의 턴이 동일하다는 뜻은 아니다.
반복 질문도 각 목록의 위치와 답변을 유지한다. 검증된 과거 답변과 일반
히스토리의 대체 안내문은 합치지 않고, 현재 근거의 인용 검증도 바꾸지 않는다.

기존 히스토리 승인·삭제 재검증·길이 제한 이후에만 투영한다. 접두사,
공백 정규화, 부분 일치로 원문을 대체하지 않으며 참조 대상이 없으면 기존
질문을 그대로 보낸다. 요청에 전달되지 않은 과거 답변을 복원하지 않는다.
저장된 대화와 현재 사용자 입력, 근거 본문, 동의 범위는 변경하지 않는다.

## 합성 검증

실제 workflow와 OpenAI bridge request mapper에 합성 근거 61,018바이트,
989바이트 질문 네 개를 전달했을 때 요청 JSON은 87,123에서 83,679바이트,
bridge JSON은 87,198에서 83,754바이트로 각각 3,444바이트 줄었다.
참조 설명과 키의 비용을 포함한 결과다. 각 질문과 근거 본문은 한 번씩
남으며 히스토리가 없는 요청은 크기가 바뀌지 않았다.

단위 회귀는 정확 일치, 부분 일치 제외, 반복 턴 순서, 경계 밖 참조 방지,
검증 답변 누락 표시와 입력 불변을 확인한다. workflow 회귀는 도구 전후의
중복 제거, 인용 복원과 payload 승인·현재 근거 재검증을 확인한다.
64KiB는 전체 요청의 강제 제한으로 다시 도입하지 않는다.

이는 합성 입력의 직렬화 크기와 실행 경계 검증이다. 실제 모델의 이해도,
응답 품질·지연, Swift HTTP 직렬화나 실기기 동작을 증명하지 않는다.
시스템 지시·스키마·인용 메타데이터 및 호출별 coverage는 역할이 다르므로
이 변경에서 임의로 제거하지 않는다. 조사와 후속 범위는 #1331에서 추적한다.
